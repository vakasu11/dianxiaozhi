# 店小智 v0.3 本地经营工作台

在商品、经营流水、三张报表和聊天查数基础上，新增 CSV/Excel 数据导入、完整期间确认、补货/低销量建议、实际执行与多次观察复盘。沿用原 Demo 的深色侧栏、浅色卡片和 ECharts 风格。

## v0.3 新增功能

### 数据导入

在“数据导入”选择商品档案或经营流水，下载对应的 CSV/Excel 模板。支持选择 `.csv` / `.xlsx` 文件，也支持粘贴 Excel 单元格内容。CSV 支持 UTF-8 与 GB18030 解码。

1. 商品档案只建立商品，不增加库存。初始库存通过“初始商品投入”流水记账，总金额填库存成本总额；后续采购使用采购入库。
2. 经营流水必须有外部流水号，且同一来源保持相同来源名称。同号且内容相同会跳过，同号但金额等内容不同会报错。采购和销售必须填写现结或赊账，总金额填整笔金额。
3. 预览中可调整字段映射；任意一行有错误时整批不写入，错误清单可导出。通过后点击确认才写入；所有数据同时进入库存、报表和聊天。
4. 导入历史支持撤销最新且未被后续业务依赖的批次。已关联后续流水、执行任务或已编辑商品时会阻止直接撤销。导入流水不能单笔拆撤。
5. 文件不上传服务器，Excel 在本地 Worker 中解析，包含公式时要求先粘贴为值。限制文件 5 MB、每次 1000 行 / 40 列、解压数据 32 MB；不支持加密文件、旧版 `.xls` 或合并单元格表头。

### 建议执行与复盘

1. 在“经营建议与复盘”确认销售记录完整的起止日期。没有完整期间，不把缺失日期补成零，也不计算日均销量；未满 7 天只做阈值提醒。
2. 商品可以设置供货提前期、安全储备天数和补货包装数量。完整观察至少 7 天、有销量时按“目标库存 = max(预警线，日均销量 × (供货天数 + 安全天数))”计算，扣除库存后按包装数向上取整。这只是历史速度参考，不包含未录入的在途采购。
3. 完整观察至少 30 天后，才对零销量或预计可售超过 90 天的商品给出低销量观察。预计可售天数不等于库存实际库龄，仍需人工核查。
4. 采纳建议只建任务；记录实际补货时生成一笔关联采购入库，不能重复执行。低销量处理只记录实际措施，不自动生成交易或改变库存。
5. 复盘比较执行前库存、执行前 7 天已录销量、执行次日至复盘日销量及观察天数，并标明完整性。当天只能标记待观察；待观察保留后续复盘入口，多次观察会留存。主观“有帮助”不等于软件已经带来可证明的因果收益。
6. 行动与复盘支持导出 CSV，可作为试点案例整理的原始材料。

旧版数据和 JSON 备份会在读取时迁移，保留原商品、流水和聊天；也增加了“粘贴备份恢复”入口。更新前仍建议导出现有备份。

## 启动

无需安装 npm 依赖。需要 Node.js 22 或更新版本，本机可使用 Codex 的内置 Node。

在项目 `app` 文件夹的 PowerShell 中运行：

```powershell
& 'C:\Users\raw_0\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' server.mjs
```

也可以双击当前目录的 `start.cmd`，或运行 `启动店小智.ps1`。浏览器访问 http://127.0.0.1:19393 。不要直接双击 HTML，模块和接口需要通过本地服务器加载。关闭服务进程不删除浏览器里的记录。

服务仅监听本机地址，当前没有云端账户及多门店权限，不能直接作为互联网公共服务部署。

## 首次使用

1. 默认打开模拟演示。右上角“进入我的门店”切换到独立、空白的真实录入模式。
2. “商品与库存 → 新增商品”：录入名称、编码、单位、价格、参考进货价及初始库存。初始库存按业主实物投入计入存货与权益；应付的历史购货款等复杂期初业务暂不支持。
3. “记一笔”：记录现金投入、采购入库、销售出库、报损、费用、收回应收款、支付应付款和业主提款。采购/销售支持现结或赊账。
4. 经营仪表盘及三张报表随记录更新。选定期间后可导出 CSV，也可使用浏览器打印保存 PDF。
5. AI 聊天页可询问“本期利润”“今天销售收入”“哪些商品需要补货”“应收应付款有多少”。默认本地问答，不调用外部模型。
6. 在“门店与数据”导出完整 JSON 备份。清理浏览器、改换端口或浏览器后不会自动出现原数据，需要使用对应模式的备份恢复。

支持按今天、昨天、本月、上月、本周、近7天、近30天或明确起止日期查询。未写期间时沿用页面的统计范围。聊天按当前门店模式分别保存。

## 财务口径

三表共同基于一套按时间排序的经营流水，金额用整数“分”保存，存货销售成本采用移动加权平均法。

- 利润表：期间销售收入 − 销售成本 − 已记录经营费用 − 报损。
- 资产负债表：截至结束日期，现金 + 应收 + 存货 = 应付 + 业主净投入 + 累计利润。
- 现金流量表：期间经营和筹资现金变动，以及期初、期末现金。实物初始投入不计现金流；赊销不立即增加现金；收款不重复确认收入。
- 只提供简化经营账，不含税费、固定资产、折旧、贷款、历史结转或完整法定会计科目；投资现金流尚未支持。不是完整法定财务报表，也不是参赛计划书的预测三表。
- 单条销售是商品流水，可能不等于一笔完整订单，因此暂不计算客单价、顾客人数或连带购买。
- 当前支持整数计件商品及基于供货周期的参考补货，暂不支持称重小数数量、批次、退货、盘点调整和箱件自动转换；补货包装数只用于数量取整。
- 业务按日期顺序录入。历史错误需按倒序撤销最后流水再重录，避免改写后续加权成本。修改商品参考价格不影响历史成本。

报表分类依据参考财政部《小企业会计准则》第八十一、八十二条，但本产品仅实现以上明确列出的经营子集：
https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852319878.pdf

## 可选的真实模型接入

本地问答已经可用。服务端提供兼容 Chat Completions JSON 格式的可选模型适配器，使用以下环境变量：

```text
CHAT_API_URL=供应商提供的完整聊天接口 HTTPS 地址
CHAT_MODEL=模型名称
CHAT_API_KEY=服务端密钥
```

在本机将 `.env.example` 复制为 `.env` 并填写，用以下命令启动：

```powershell
& 'C:\Users\raw_0\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --env-file=.env server.mjs
```

普通启动不会自动读取 `.env`。不要把密钥发到聊天里，不要提交 `.env`，不要写入前端。外部模型地址必须为 HTTPS；本机模型允许回环 HTTP。配置完成重启后，聊天页会出现“使用已配置模型”的选项，勾选才发送本次问题与商品/财务汇总。不会发送完整流水、历史会话或备注。不要在问题里填写不必要的个人信息。

模型请求限制问题长度、请求大小和同一客户端并发，25 秒超时，失败后切回本地问答。适配器用本地模拟服务进行了协议测试，未使用真实密钥，也未验证某个商业供应商的在线响应。

## 数据保存与代码

- `public/domain.mjs`：商品、流水、库存成本、三张报表及本地问答。
- `public/storage.mjs`：浏览器本地保存、模式隔离、版本和多标签页冲突检查。
- `public/app.mjs`：页面、表单、交互、导出恢复和聊天。
- `public/demo.mjs`：基于同一业务逻辑生成的明确标记的演示数据。
- `public/importer.mjs`、`public/excel-worker.js`：字段映射、CSV/Excel 解析、整批试算、去重与撤销。
- `public/workflow.mjs`、`public/screens.mjs`：完整期间、建议、行动、执行及复盘页面。
- `server.mjs`：本机静态服务与可选模型代理。只公开 `public` 文件夹。
- `tests/`：库存、财务、保存、接口与错误边界测试。

存储使用 localStorage，保存失败会显示错误，不将未写入的数据显示为已成功保存。数据格式有版本号，恢复前检查结构及账目；另一个标签页已经更新时会拒绝覆盖。适用于本地少量记录的第一阶段，后续大规模数据导入应迁移为 IndexedDB 或服务端数据库。
