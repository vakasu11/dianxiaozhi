## v0.4 第二阶段

- **订单与商品分析**：记销售/导入可填订单编号及成交时间（HH:mm）。按同日同号合并，展示客单、每日/小时订单、销售与毛利排行及组合出现次数。未编号记录只计入商品与收入统计；不推算顾客人数。订单号允许跨日重复，同日结算与时间需一致。
- **选品与试销**：先查看在售表现，再登记候选来源、原因、参考价格；候选可直接建档，但不会自动增加库存。7/14/30天结果需周期已满且完整销售记录覆盖。结束时保留结论；不虚构新品预测。
- **活动与文案**：基于实际商品和成本生成草稿，低于成本需要明确确认；可编辑、复制、登记实际执行。已配置模型时可发送本条活动润色，返回先核对再保存，不自动发布。
- **经营报告**：期间、近7天/30天，汇总业务、已处理建议采纳、执行复盘、反馈和工时；匿名CSV及带收入图表的HTML，HTML可由浏览器打印PDF。采纳状态为当前记录，执行/复盘限定截止日；短期变化不作为因果收益证据。
- **成本与反馈**：团队服务工时及实际费用与门店财务分开；记录模型调用用量、耗时和结果。输入/输出费率按人民币元/百万token填写，费用以调用当时费率保存。价格或用量未知时待核实。反馈可分类、分级、关联行动并跟踪处理。
- **PWA**：首次联网准备资源后，本机服务停止仍可打开与保存本机记录；状态和业务日期可见。更新由用户确认后整体载入，保留已保存数据。支持的Edge/Chrome可通过菜单安装；手机需可访问的HTTPS发布地址，当前回环地址仅本机可用。安装不是跨设备同步。

数据结构升级为v3并兼容旧v1/v2备份，原存储键不变。升级前建议导出备份。旧版演示记录不自动伪造订单号；用“我的门店”录入独立数据。

本次48项测试及浏览器走查见 [验收记录](../docs/phase-two-validation.md)。系统安装、真实供应商响应与真实门店效果尚未验证。

## v0.3 已有功能


### 数据导入

在“数据导入”选择商品档案或经营流水，下载对应的 CSV/Excel 模板。支持选择 `.csv` / `.xlsx` 文件，也支持粘贴 Excel 单元格内容。CSV 支持 UTF-8 与 GB18030 解码。

1. 商品档案只建立商品，不增加库存。初始库存通过“初始商品投入”流水记账，总金额填库存成本总额；后续采购使用采购入库。
2. 经营流水必须有外部流水号，且同一来源保持相同来源名称。同号且内容相同会跳过，同号但金额等内容不同会报错。采购和销售必须填写现结或赊账，总金额填整笔金额。
3. 预览中可调整字段映射；任意一行有错误时整批不写入，错误清单可导出。通过后点击确认才写入；所有数据同时进入库存、报表和聊天。
4. 导入历史支持撤销最新且未被后续业务依赖的批次。已关联后续流水、执行任务或已编辑商品时会阻止直接撤销。导入流水不能单笔拆撤。
5. 文件不上传服务器，Excel 在本地 Worker 中解析，包含公式时要求先粘贴为值。限制文件 5 MB、每次 1000 行 / 40 列、解压数据 32 MB；不支持加密文件、旧版 `.xls` 或合并单元格表头。

### 建议执行与复盘

1. 在“经营建议与复盘”确认销售记录完整的起止日期。没有完整期间，不把缺失日期补成零，也不计算日均销量；未满 7 天只做阈值提醒。
2. 商品可以设置供货提前期、安全储备天数和补货包装数量。完整观察至少 7 天、有销量时按“目标库存 = max(预警线，日均销量 × (供货天数 + 安全天数))”计算，扣除库存后按包装数向上取整。这只是历史速度参考，不包含未录入的在途采购。
3. 完整观察至少 30 天后，才对零销量或预计可售超过 90 天的商品给出低销量观察。预计可售天数不等于库存实际库龄，仍需人工核查。
4. 采纳建议只建任务；记录实际补货时生成一笔关联采购入库，不能重复执行。低销量处理只记录实际措施，不自动生成交易或改变库存。
5. 复盘比较执行前库存、执行前 7 天已录销量、执行次日至复盘日销量及观察天数，并标明完整性。当天只能标记待观察；待观察保留后续复盘入口，多次观察会留存。主观“有帮助”不等于软件已经带来可证明的因果收益。
6. 行动与复盘支持导出 CSV，可作为试点案例整理的原始材料。

旧版数据和 JSON 备份会在读取时迁移，保留原商品、流水和聊天；也增加了“粘贴备份恢复”入口。更新前仍建议导出现有备份。

## 启动

无需安装 npm 依赖。需要 Node.js 22 或更新版本，本机可使用 Codex 的内置 Node。

在项目 `app` 文件夹的 PowerShell 中运行：

```powershell
& 'C:\Users\raw_0\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' server.mjs
```

也可以双击当前目录的 `start.cmd`，或运行 `启动店小智.ps1`。浏览器访问 http://127.0.0.1:19393 。不要直接双击 HTML，模块和接口需要通过本地服务器加载。关闭服务进程不删除浏览器里的记录。

默认服务仅监听本机地址。CloudBase 包由启动脚本启用云模式和邀请码；它是小范围答辩测试，不提供商用多租户账户或云账本。

## 首次使用

1. 新设备默认进入空白的“我的门店”。右上角“查看演示”可打开独立的模拟数据；已有设备沿用原选择。
2. “商品与库存 → 新增商品”：录入名称、编码、单位、价格、参考进货价及初始库存。初始库存按业主实物投入计入存货与权益；应付的历史购货款等复杂期初业务暂不支持。
3. “记一笔”：记录现金投入、采购入库、销售出库、报损、费用、收回应收款、支付应付款和业主提款。采购/销售支持现结或赊账。
4. 门店概况及三张报表随记录更新。选定期间后可导出 CSV，也可使用浏览器打印保存 PDF。
5. 经营问答页可询问“本期利润”“今天销售收入”“哪些商品需要补货”“应收应付款有多少”。默认本地问答，不调用外部模型。
6. 在“门店与数据”导出完整 JSON 备份。清理浏览器、改换端口或浏览器后不会自动出现原数据，需要使用对应模式的备份恢复。

支持按今天、昨天、本月、上月、本周、近7天、近30天或明确起止日期查询。未写期间时沿用页面的统计范围。聊天按当前门店模式分别保存。

## 库存盘点

在“库存盘点”或商品行的“盘点”入口，先核对账面，再填写实盘整数数量（可以为零）、日期与原因，预览差异后确认。盘亏按当前加权成本计入损失；盘盈按当前平均成本估值，原库存为零时用当时参考进价，并保存估值依据。先补齐当天业务，不可插入到已有流水之前。错误盘点可在经营流水按顺序撤销。盘点暂不支持批量导入。

## 财务口径

三表共同基于一套按时间排序的经营流水，金额用整数“分”保存，存货销售成本采用移动加权平均法。

- 利润表：期间销售收入 − 销售成本 − 已记录经营费用 − 库存损失（报损 / 盘亏）+ 库存盘盈收益。盘点不产生营业收入、销售数量或现金。
- 资产负债表：截至结束日期，现金 + 应收 + 存货 = 应付 + 业主净投入 + 累计利润。
- 现金流量表：期间经营和筹资现金变动，以及期初、期末现金。实物初始投入不计现金流；赊销不立即增加现金；收款不重复确认收入。
- 只提供简化经营账，不含税费、固定资产、折旧、贷款、历史结转或完整法定会计科目；投资现金流尚未支持。不是完整法定财务报表，也不是参赛计划书的预测三表。
- 单条销售是商品流水，可能不等于一笔完整订单，有编号时统计已记录订单客单与组合；无编号不计算精确订单指标，也不据此推断顾客人数。
- 当前支持整数计件商品及基于供货周期的参考补货，暂不支持称重小数数量、批次、退货和箱件自动转换；补货包装数只用于数量取整。
- 业务按日期顺序录入。历史错误需按倒序撤销最后流水再重录，避免改写后续加权成本。修改商品参考价格不影响历史成本。

报表分类依据参考财政部《小企业会计准则》第八十一、八十二条，但本产品仅实现以上明确列出的经营子集：
https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852319878.pdf

## 可选模型与服务端配置（v0.6.2）

默认使用本地规则问答。联网、后端已配置且邀请码验证通过后，经营问答页会提供模型选项，每次发送需单独确认本次问题与必要经营汇总的发送范围。CloudBase 由账号持有人在函数环境变量填写 `GLM_API_KEY`，模型固定为 `glm-4-flash-250414`；完整云配置见 [CloudBase 部署指南](../docs/cloudbase-deploy.md)。

本机服务也保留兼容 Chat Completions JSON 格式的可选适配器，配置以下环境变量：

```text
CHAT_API_URL=供应商提供的完整聊天接口 HTTPS 地址
CHAT_MODEL=模型名称
CHAT_API_KEY=服务端密钥
```

在本机将 `.env.example` 复制为 `.env` 并填写，用以下命令启动：

```powershell
& 'C:\Users\raw_0\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --env-file=.env server.mjs
```

普通启动不会自动读取 `.env`。本机也可通过 `GLM_API_KEY` 使用固定的智谱模型。密钥只能放服务端，不得放进手机前端或静态发布资源。

模型请求限制问题长度、请求大小和同一客户端并发，上游 25 秒超时，失败后可继续本地问答。自动化协议测试使用本机模拟服务；公网 GLM 真实请求已另用模拟经营数据验证。两类证据分别记录，不能代替真实商户使用或真实模型页面流程的验收。

## 数据保存与代码

- `public/domain.mjs`：商品、流水、库存成本、盘点、三张报表及本地问答。
- `public/stocktake-view.mjs`：盘点录入、预览确认与历史核对。
- `public/storage.mjs`：浏览器本地保存、模式隔离、版本和多标签页冲突检查。
- `public/app.mjs`：页面、表单、交互、导出恢复和聊天。
- `public/demo.mjs`：基于同一业务逻辑生成的明确标记的演示数据。
- `public/importer.mjs`、`public/excel-worker.js`：字段映射、CSV/Excel 解析、整批试算、去重与撤销。
- `public/workflow.mjs`、`public/screens.mjs`：完整期间、建议、行动、执行及复盘页面。
- `public/business.mjs`、`business-schema.mjs`、`business-views.mjs`：订单、试销、活动、报告、服务、模型成本与反馈。
- `public/report-export.mjs`：匿名HTML报告与收入图表。
- `public/pwa.mjs`、`sw.js`、`manifest.webmanifest`：安装、离线资源及更新；修改发布资源后需更换Service Worker缓存版本。
- `public/merchant.css`：v0.4门店工作台主题与手机抽屉导航。
- `server.mjs`：本机静态服务与可选模型代理。只公开 `public` 文件夹。
- `tests/`：库存、财务、保存、接口与错误边界测试。

存储使用 localStorage，保存失败会显示错误，不将未写入的数据显示为已成功保存。数据格式有版本号，恢复前检查结构及账目；另一个标签页已经更新时会拒绝覆盖。适用于本地少量记录的前两阶段，后续大规模数据应考虑迁移为 IndexedDB，仍遵守当前本地保存要求。

## 发布与安装

GitHub仓库用于版本管理，不自动发布店铺数据。当前本机服务仅接受回环地址，不应直接暴露成公共API。

如仅发布本地数据版前端，可将 `public/` 作为静态站点托管到 HTTPS；模型接口不可用时仍使用本地问答。当前 CloudBase 测试服务已有邀请码会话、同源校验、调用限频和测试截止控制，默认测试域名可能出现平台访问提示或限流。站点文件、模型密钥、用户业务数据分开保存；本版本为单门店本机数据应用，邀请码用于短期在线试用。

安装入口由浏览器提供。PWA最低要求参考 [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)：应用清单、图标及HTTPS/本机环境。手机安装体验需在目标设备再验证。
