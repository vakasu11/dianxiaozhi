# 店小智 v0.6 手机本地版

本次按“先本地部署、AI后续再接入”交付。网页不调用外部模型，不接收API密钥，不上传门店记录。原有商品、库存、流水、三表、导入、建议复盘及本地问答保留。

v0.6 在此基础上加入“库存盘点”：逐商品核对实物与账面、预览差异、确认后记录盘盈 / 盘亏及原因。当前完整进度见 [开发进度](progress.md)。

## 本机运行

在 `app` 目录双击 `start.cmd`，保持服务窗口开启。默认打开 `http://127.0.0.1:19393/`，首次联网载入后准备离线缓存。需要 Node.js 22 及以上；启动脚本会优先寻找本机 Codex 已有的 Node，否则使用系统 Node。

首次打开进入空白“我的门店”，在门店概况选择“建立第一个商品”。既有设备保留原数据和数据模式；不会把旧演示订单补造为新订单。

127.0.0.1 是当前设备本身。电脑上的这个地址不能直接交给手机使用。手机独立使用PWA需要可访问的HTTPS发布地址；当前交付先完成本机运行、手机尺寸验收和静态部署包，未宣称已经公网发布或完成真机系统安装。

## 手机数据保存与备份

- 所有业务记录保存在当前设备、浏览器和应用路径的 localStorage 中，不设云端数据库，不会自动跨设备同步。同一域名的其他Pages项目使用不同存储前缀，避免项目间混用。
- “门店与数据”可申请浏览器持久保存；是否许可由浏览器决定。即使得到许可，主动清理浏览器仍会删除记录。Safari、其他浏览器和主屏幕入口的存储共享行为需真机验证。
- 定期导出完整JSON备份，并在手机文件或下载列表确认保存。界面记录的是“发起导出”时间，不冒充已确认写入手机文件。
- 换设备时，在新设备选相同数据模式，再通过文件或粘贴方式预览恢复。恢复会替换该模式当前记录，先保留旧备份。
- 原始数据、演示和真实模式相互隔离。空间不足时本次写入报错，不把失败记录显示为已保存。

## 静态部署包

运行 `cd app` 后 `npm run build:pages`，输出到项目 `output` 下的新目录。部署目录只包含 `public/` 的网页、图标、本地脚本及许可证，不包含服务端、密钥、备份、聊天或验收门店记录。

目录内包含 `.nojekyll`，模块、图标、清单与Service Worker都使用相对路径，可部署到GitHub Pages的项目子路径。缓存按应用路径区分，升级只清理本工具在同一路径的旧资源缓存，不清理业务记录。

已生成的静态ZIP只适合HTTPS静态托管，不应直接双击HTML替代HTTP服务。完整本地运行包则包含本机静态服务和Windows启动脚本。

## 验证结果

54项自动测试通过。浏览器以纯静态子路径 `/dianxiaozhi/` 运行，没有模型服务接口。实际CSS宽375、页面scrollWidth375；建商品、10瓶初始库存、销售2瓶（每瓶3元/成本1元），刷新后收入6元、利润4元正确。实际JSON下载及粘贴预览恢复已通过；恢复后门店名称、1个商品、2条流水一致。持久保存申请被当前测试浏览器拒绝时，界面显示拒绝并保留现有记录。

停止纯静态测试服务后，重新载入与本地利润问答仍可用；离线新增反馈后刷新仍保留。本机默认19393入口完成v0.4→v0.5整包更新，原26条演示流水保留。

系统级手机安装、真实商户使用和公网访问未验证。原P0遗留的退货、箱件换算与临期批次仍需独立实现。
