# 第二阶段交付计划

目标：将现有经营数据、规则建议和财务三表扩展为可持续试用的门店工具，并在私有 GitHub 仓库维护。

## 范围

| 事项 | 实现方向 |
| --- | --- |
| Excel 与辅助录入 | 复用已验证导入流程，补充订单编号与成交时间 |
| 解释与问答 | 服务端模型适配、用量与失败记录、本地回退、依据与期间 |
| 客单分析 | 只统计有订单编号的销售明细；呈现覆盖率、客单、时段和组合出现次数 |
| 选品与试销 | 在售分析、店主提供来源的候选、关联商品后观察 7/14/30 天 |
| 活动文案 | 实际售价、成本及活动日期形成草稿，核对后复制，执行单独登记 |
| 经营报告 | 期间业务、建议采纳执行、反馈、服务投入，匿名导出 |
| 应用体验 | 应用清单、图标、离线缓存、联网状态、更新提示 |
| 成本与反馈 | 团队服务工时/费用、模型用量及价格估算，反馈分级跟进 |

## 界面方案

用户是小门店店主及学生陪跑团队。主要任务是录入、核对和处理经营问题。

- 色彩：工作区 #F6F7F9、纸面 #FFFFFF、正文 #1F2937、次要信息 #64748B、业务操作 #0F766E、边线 #D8DEE6。
- 字体：沿用 Windows/系统中文字体，保证现有电脑和手机无需下载字体即可清楚阅读；数字采用等宽数字排版。
- 布局：白色侧栏分业务、分析、财务和设置；内容以表格、明细和简明指标组织。页面标题左对齐，主操作固定在标题区域。
- 移动端：明确的菜单按钮与抽屉，避免导航隐藏在横向滚动区域。
- 文案：使用“记销售”“导入流水”“经营问答”“记录执行”等具体动作；删除宣传性副标题、英文装饰标签和模型拟人化状态。

```text
侧栏         门店名称                 保存 / 联网状态
业务         页面标题                         主要操作
分析         期间选择
财务         业务摘要 / 待处理事项
设置         核心表格、趋势与明细
```

方案复核：不采用大幅主视觉、紫蓝渐变或装饰性数字卡片；优先让真实数据口径、覆盖不足及操作结果清楚可见。设计技能只辅助视觉与文案判断，业务计算仍由测试验证。

## 边界

真实模型在线调用取决于本机供应商配置；不伪造调用结果。真实门店效果需要后续试点；候选商品、价格和反馈是用户记录，不冒充市场验证。PWA 在本机或 HTTPS 环境可使用，公共云端登录与多门店权限属于下一阶段。
