# 本地账本迁移与核验

适用于从原本机网址（例如 `http://127.0.0.1:19393/`）迁移到已部署的 HTTPS 网站。不同地址、不同浏览器的数据空间互相独立；部署源码不会自动迁移账本。

## 迁移前保留两份原始文件

1. 在原本机网页打开“门店与数据”，确认右上角是要迁移的“真实录入”或“模拟演示”。
2. 点击“导出完整备份”，在下载列表确认 JSON 已落盘，保存为原始备份。真实和演示分别导出，不要互相替代。
3. 在目标 HTTPS 网页也先导出相同模式的现有备份，即使目标当前为零条记录也先保留。恢复会替换该模式的目标数据。
4. 原始文件在迁移完成前保持不修改；无需上传 GitHub、云数据库或发给模型。

## 恢复到新网址

1. 在固定浏览器打开已发布的 HTTPS 地址，通过邀请码进入。
2. 切换到与原始备份一致的数据模式。
3. 在“门店与数据”点击“选择备份恢复”，选择原始 JSON；也可用“粘贴备份恢复”。
4. 核对预览中的店名、商品、业务和行动条数，再保存恢复。
5. 重新载入页面，核对商品库存、流水、聊天和三张报表。使用相同统计起止日期比较，确保不是日期差异造成数字不同。
6. 在目标网页再次导出完整备份，作为恢复后备份。在比较完成前不要新增业务、提问或修改费率，以免改变核验对象。

## 文件一致性核验

在项目 app 目录运行：

```sh
node scripts/verify-backup.mjs 原始备份.json 恢复后备份.json
```

`matches: true` 表示迁移后的完整业务内容一致。核验包含店名、商品、流水、聊天、行动、试销、活动、反馈及调用记录；只忽略恢复保存时正常变化的 revision / updatedAt。工具同时检查备份模式、数据结构、库存与账目校验，并输出商品 / 业务条数及累计简化财务汇总，不输出聊天或邀请码。

退出码为 0 表示核验通过，为 1 表示文件无效或不一致。比较失败时保留原始文件和目标迁移前备份，不要清空原浏览器；先确认是否选错模式或恢复后又新增了记录。

该工具是只读检查，不会自动修改、上传、恢复或删除文件。终端中含空格的文件路径需用引号包住。核验结果也不要作为真实商户效果证明。

## 手机验收

在实际手机浏览器中恢复后，重新打开确认记录保留，联网准备离线资源；再开启飞行模式测试查询 / 录入 / 报表 / 备份。离线不能调用 GLM。浏览器添加到主屏幕后，再从新增入口检查记录是否共享。电脑窄屏和单元测试不能替代这些真机步骤。
